# Athanor changes - October 2, 2026

This update expands physical testing and makes the same building blocks easier for users and agents to reuse.

## For testers

- Fresh workspaces default to **Logan's checklist - full automated course** (`smoke-full`): 153 checks, including 137 accepted definitions and 16 qualification candidates. Existing explicit course choices remain saved.
- **All automated checks** (`automated-full`) keeps the 137 accepted definitions. **Build engine checks** (`packaged-full`) keeps the 57 engine checks. Custom courses remain accepted-only.
- The default adds 13 physical paths: six Spellbook paths plus bin drop/overwrite, Render Graph move/pan, wiring, clipboard, trim and live curve sampling.
- Three additional candidates exercise external timeline reload, source-colour override and generated-graphic bin drop/playback. The provisional idle CPU candidate is retained for a separate later run, outside the default.
- Independent physical and checklist checks use fresh projects and sessions. Ordinary failures remain in the report while unrelated checks continue after confirmed cleanup.
- Reports retain actions, native input receipts, graph/timeline observations and captures from the session that actually produced them. Earlier attempts stay intact.
- Build imports show live transferred bytes and percentage when the total is known, followed by archive checking, unpacking and app verification. The same progress is available to agents through the local API.

- Build discovery starts with 10 records. Local listings read metadata; selected downloaded packages retain full identity verification. Import verification advances at completed steps, then selects the build and closes the finder.

## For agents and test authors

- Use the dashboard, CLI, application operations, Qt observations and verified physical input independently. Courses select behaviors; checks declare their own setup and prerequisites.
- Keep fixture setup, the tested action, independent assertions, evidence and cleanup separable. Reuse the production state assertions when authoring related checks.
- Read [test authoring](test-evidence.md#compose-a-test-from-reusable-parts) for bin drop, graph wiring, trim and live-preview examples, plus a runnable assertion example that needs no Wizard app.
- Export `context --check ID --export --server URL` for the definition, implementation pointers, editing prompt and reference guidance. Use a source checkout for edits.
- Agent attempts enforce definition-owned actions and checkpoints before Pass. A fresh attempt preserves the earlier result. An uncertain action remains Unknown and requires inspection.
- Execution uses the retained source snapshot. New code or definition changes need a fresh plan. Candidate acceptance remains a lead decision.

## Run this update

1. Install the new versioned bundle, or start the updated checkout with `npm run open` from `smoke/`.
2. Choose the exact Wizard build and course. Prepare build attaches matching external tools to a disposable copy of that package and shows progress or a repair prompt.
3. Keep the Mac unlocked and available for foreground checks. The default course excludes the ten-minute idle measurement; run that candidate separately when the Mac can remain idle.
4. Start checks, then click a Results row for its expected result, actions and evidence. Keep failures and blocked attempts when rerunning.

Node.js 24+, local media tools and selection-specific model inputs remain prerequisites. A matching bundle supplies desktop tools; source-only setup needs a matching SDK/compiler. Runtime data stays outside Git. Story-user, Large, NAS and the fuller human-handoff workflow remain future work.

## Agent guidance and focused investigations

- Start from the task table in AGENTS.md. Courses, computer use, investigations and harness maintenance each have a short entry point. Current counts come from `list` and `courses`.
- Session usage now includes `tool`. Session context distinguishes scripted assertions, qualified interactive verdicts and exploration, and reports the automatic shutdown deadline.
- Physical keys now cover transport, In/Out marks, blade, arrows, digits, function keys and navigation/nudging. Process and focus guards remain in place.
- Observations expose incomplete model, scene and menu data. Scene flags distinguish a full result at the cap from a truncated result on new adapters; older adapters report conservatively.
- A bin-duplicate repro retains its connection checks, rename independence and save/reopen verification without selecting the neighboring seven checks or creating their render fixture. New plans use this closure; frozen earlier runs remain unchanged.

## Investigation review packages

- Packages now open with a portable Athanor reviewer page: expected and observed behavior, retained procedures, process-labeled before/after captures, state/log links and bug drafts. The page works from the exported folder.
- Agents get `review-data.json` with attachment roles and exact retained identities; people get individual draft text files. Human confirmation remains in the live investigation.
- New captures retain timestamps and launch generation. Draft qualification checks same-process before/after captures and case-owned attachment paths and hashes, including deduplicated source aliases. Old packages and verdicts remain intact.

## Bug Reporter bridge

- Primary app cases can export draft fields, a retained failure screenshot, bounded logs and an indexed evidence parcel through the investigation UI or CLI. Missing evidence stays visible as work to complete.
- The attached Qt plugin supports draft-only Report Bug prefill with exact field readback. Existing manual drafts and frozen pending reports are preserved; the helper stops before Submit and retains a receipt.
- App-owned CLI draft/capture/import support is being implemented separately. Current field prefill leaves historical attachments in the parcel.

## Navigation and investigation follow-up

- Investigations is a permanent workspace view alongside Run tests, Results and Checks, including on the Test guide and investigation pages.
- Search investigations by title or build. Multi-select next-step filters and named views use the existing browser-local filter system.
- Results links to investigations from first runs and linked focused repros. Opening a linked repro returns to its original investigation.
- Investigation stages open the first report, package agent context, reveal diagnostic setup and reach human review. Draft text and package paths are secondary disclosures.
- [Studio hosting](studio-hosting.md) describes the proposed private single-runner pilot, access requirements and growth path. Deployment is a separate step.
