# Athanor update — October 11, 2026

This update improves failed-check investigation, agent handoffs and canceled-run
cleanup. Developer clones continue to use the ordinary local harness. Managed
workers use the same runner through the job controller.

## Investigation and evidence

- Test details show recorded expected and observed values, the failed phase,
  last completed phase and reasons later phases did not run. Full source excerpts
  remain in checksummed assertion evidence.
- Media Bin graphic duplication, right-edge trim and vectorscope checks retain
  their measured comparison alongside the existing independent assertions.
- Authored step dependencies explain unavailable work; they do not dispatch
  actions or turn incomplete tests into app defects.
- Portable investigations include `tasks/TASK-first-read.json`. Managed job
  reports include a first-read packet, investigation links and the local command
  root, service URL and stage-specific recovery commands.
- New prepared runs retain failure/repro images and required passing visual
  proof. Disposable passing intermediate PNGs are pruned only after report
  retention, with immutable checksums. Historical runs keep their frozen policy.

## Lifecycle and measurements

- Background service courses now reuse the foreground executor's verified
  termination fallback when normal shutdown is blocked by an interrupted call.
  Process ownership is checked before signaling; the interrupted evidence stays
  intact. Ordinary test failures still continue into independent checks.
- Desktop reports retain prepare, launch, reopen, close and cleanup intervals.
  Diagnostic receipts retain collection duration.
- `node scripts/review-cost.mjs` compares packet size and recorded intervals.
  Reviewer latency requires an evaluated reviewer session; smaller packets alone
  are not a measured agent speedup.

## Acceptance and worker update

Changed test definitions retain their historical acceptance pins and remain
qualification candidates until reviewed. Legacy assertion mappings whose
definitions changed need review; related catalog checks do not replace those
assertions automatically.

Before an MBP update, review and verify a clean source revision, install it in a
new versioned checkout, generate a matching worker/controller profile, and switch
only the idle owned services. Keep the schedule paused until selected-package
acceptance, report retention, cancellation cleanup and private delivery are
verified. Preserve the previous source/profile/workspace for rollback. Prepare
new plans; never edit a frozen plan or resume uncertain input.

This update does not enable autonomous triage, change Slack recipients, submit
bugs or enable the nightly schedule. See [job controller](job-controller.md),
[investigations](investigations.md) and [worker updates](workers.md#updates-and-rollback).
