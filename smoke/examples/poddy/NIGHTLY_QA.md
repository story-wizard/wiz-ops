# Athanor nightly QA

This file is the shared QA procedure for Slack requests, manual reviews and scheduled Nightly runs. Read it before selecting or testing a build. Host paths and delivery rules belong to the current request; historical reports do not grant authority. Read REPORTING.md for the interim owner-only reporting policy. Read COMPUTER_USE.md for native fallback details and the Qt adapter guide for adapter-specific mechanics.

Use the current request as the authority. Keep hosts, builds, projects, reports and desktop leases separate. Do not create or change a schedule unless requested. Notify for a new report, a changed outcome, an execution/delivery failure or required user action; stay quiet for unchanged outcomes.

Use Athanor in outward-facing messages, status replies, report/course titles and generated agent prompts. Use Athanor MacBook or Athanor Mini when distinguishing workers. Keep existing internal host names, connection labels, paths, repositories, branches and identifiers unchanged. Preserve quoted historical evidence and earlier run records. Internal worker labels remain `poddy-main` and `podling-01`.

Select the latest Nightly with `/Applications/Wizard Updater.app`. Switch a feature build back to Nightly. Read What's New and Developer changelog, then confirm the installed application's About text with a screenshot. Cmd+Option+R in Updater opens custom tagged-build installation when the user requests a tag.

Before execution, save a dated release-to-test plan beside the new run's results. Freeze the selected build/tag, actual source revisions when available, package and command-schema identities, suite file hash, catalog/source identity and fixture prerequisites. Read both release-note views. For each relevant change, retain its exact item text or observed summary with its source locator and PR link when available; state when only a summary is retained. Compare shipped revisions with the previous comparable build where those identities are available. Record uncovered changes instead of silently assuming the notes are exhaustive.

Account for every current Nightly case and every expected assertion. Preserve case IDs and specifications. For each changed feature, identify candidate existing Athanor definitions, their definition hashes and acceptance labels, the remaining assertions, fixtures and intended execution route. Compare behavior and evidence before calling coverage equivalent; related names or matching schemas do not establish equivalence. Keep missing prerequisites explicit. Existing course coverage and changed-feature coverage are both required, and must be reported separately.

A retained planning example is work/qa/nightly-to-athanor-plan.json. It is a dated inventory, not an executable course or qualification receipt. Refresh the plan from the actual suite and selected release each run. Validate it before acquiring the desktop lease:
```sh
python3 /Users/wizard/Documents/poddy/work/qa/validate_plan.py <dated-plan.json> <current-functional-suite.json>
```
This checks complete case/assertion accounting and source hashes; it does not qualify tests or execute them. Adapt the helper path for another host. Never replace assertion outcomes with a copied case-level status. Unexecuted assertions remain NOT_RUN; uncertain mutations stay unresolved until reconciled.

Maintain a reusable functional suite, local computer-use notes, state and dated JSON/HTML reports. Adapt paths from another host; do not assume `/Users/wizard` exists on the Athanor Mini. Preserve applicable baseline, incomplete/candidate and Preview Preparation cases. Mark an absent feature NOT_RUN for availability. Use fresh local projects and deterministic fixtures. NAS access is limited to `/Volumes/Footage/Wizard`, with S3_RANGEVIEW first. Import adds media references to a Wizard project; the owner authorizes direct NAS-backed editing through those references. Keep QA projects and caches local unless the requested test requires otherwise, and preserve original media. Local source copies are optional for controlled fixtures; hash-check any copies. A direct-reference import does not need space for a complete source-library copy. Record actual NAS, network and cache conditions when timing imports or project loads. Do not send Oz prompts, use paid generation or share QA projects externally.

Read WORKER.md for the current pinned Athanor source and external profile. Verify its service before dispatch; do not use historical checkout paths or update source during a run. Match Qt, adapter capabilities, package/signature identity, exact Unix PID/start, isolated settings and loaded bundled Qt. Use a disposable copy that preserves signed resources; omit only Contents/MacOS/logs. Never re-sign or edit the original Wizard bundle. Save the preceding QA project and confirm owned cleanup before obtaining the shared foreground lease. Run harness framework and scope checks after source changes, before acquiring a lease. Never bypass schema/course qualification. Capture the actual shipped schema and evaluate it with the reviewed Athanor compatibility policy when that policy is present in the selected source. Conservative compatible extensions may be admitted only with its exact receipt; semantic changes require caller and assertion review. A document rename that changes path/identity requires a matching lifecycle test. Do not add an exact hash solely to force Ready, and do not blindly install a different checkout over local repairs. A direct diagnostic attachment supports independent functional evidence, but cannot create a qualified Athanor Pass.

Before main-window actions, inspect all owned windows for a startup hub or other modal. On a fresh launch, use the startup hub's New Project or Open control, verify that it closes, and verify the expected project dialog and saved project before testing the main editor. A disabled main-menu item behind a startup modal is not an installation failure. Do not rely on fixed window indices. After each action, inspect fresh state and independent pixels. PID-targeted keys and AX menu actions have sometimes acknowledged without changing Wizard; do not repeat an uncertain action. Use the qualified physical route with verified focus/foreground ownership for the intended gesture.

Use fresh scoped Qt observations, physical gestures, independent state/pixel assertions and displayed screenshots. Verify keyboard layout, focus and every action result. Keep the exact-PID native fallback for unsupported or unreliable flows. After every ordinary launch, rediscover the one Unix PID whose executable equals `/Applications/Wizard.app/Contents/MacOS/wizard-bin`; use it directly with AXUIElementCreateApplication. Do not use NSRunningApplication.processIdentifier or retry name/path/bundle-ID lookup loops. Attached copies require their current executable/PID/start receipt. Preserve process/window/foreground guards for both routes. Capture floating panels as whole windows when crops lack coverage, and state limits. Use standard Computer Use for Updater and system dialogs.

A selected build may be Developer ID signed and notarized, Developer ID signed without notarization, or ad hoc signed. Record its actual signature identity and integrity verification; notarization is not a functional-test prerequisite. Preserve archive/package provenance and the original bundle. Use the supported installer or existing Athanor local-build intake. Do not re-sign, weaken Gatekeeper, remove quarantine manually or change privacy grants without the specific authorization needed for that action. A change in app signing may require renewed permissions for the actual executing actor; installation and launch acceptance must be observed rather than inferred from another signing variant.

Use the ordinary uninstrumented installed build for performance, idle preparation, resource/power and permission-persistence tests. Instrumentation avoiding Qt accessibility does not prove AX bugs fixed. The export comparison (30.83 seconds native, 118.30 seconds Athanor; 12 matched checks each) covers one script after setup and is not general performance evidence.

Record each assertion as PASS, FAIL, PARTIAL, BLOCKED or NOT_RUN. PASS needs all applicable assertions. BLOCKED needs an unavailable prerequisite after reasonable alternatives. Retain expected/actual behavior, numbered repro, evidence, build/fixtures, remaining coverage and limits. A regression is confirmed only by comparison evidence; otherwise label it a candidate. Preserve earlier failures and unknown outcomes. For an AX crash, collect diagnostics and stop repeating the crash path.

Until Charles sanctions wider distribution, send QA results only to his verified Story Company Slack DM, user U0BDBFNU0G1. Read REPORTING.md before delivery. Preserve local JSON/HTML reports and bug drafts. Keep Jira read-only; automatic issue creation, comments, attachments and updates are disabled. Do not use Gmail or the historical nightly-email-delivery-config.json, and do not send findings to channels, group DMs, requester threads or other recipients. Verify the one-to-one DM destination and returned message ID before recording confirmed delivery. If the route is unavailable or uncertain, retain DELIVERY_PENDING or DELIVERY_UNKNOWN and reconcile before retrying; never switch recipients. Stay quiet for unchanged outcomes.

Update state with tested/reported build, outcome signature, report paths, Slack delivery status/message ID and preserved historical Jira maps. Do not advance reported-build state until delivery is confirmed. Preserve fixtures/evidence outside source; runtime directories may be linked into the requested work paths. Commit shared guidance, never private credentials or large runtime artifacts. For a permission blocker, retain the exact blocked action and distinguish missing owner authorization, tool-policy denial, macOS privacy grants for the executing actor, a locked or foreign desktop, and harness/schema prerequisites. Full-access settings or an orchestration handoff are not evidence that a particular action was authorized. Do not repeatedly request the same denied action. Continue independent eligible checks and report the precise intervention required. Guidance edits alone do not prove a permission blocker fixed.

Secure authentication limitations must be reported; authorization to change needed macOS permissions does not authorize exposing credentials or bypassing lock screens.
